# sparsesvn

A declarative, idempotent SVN sparse checkout management tool. Define which paths you want from an SVN repository in a YAML file, and `sparsesvn apply` makes your working copy match — like `terraform apply` for SVN sparse checkouts.

## Installation

### From source

```bash
go install github.com/hongy3025/sparsesvn/cmd/sparsesvn@latest
```

### Pre-built binaries

Download from [GitHub Releases](https://github.com/hongy3025/sparsesvn/releases).

### Prerequisites

- `svn` command-line client must be in your `PATH` (version >= 1.6 for `set-depth exclude` support)

## Quick Start

Create a `sparsesvn.yaml` configuration file:

```yaml
url: svn://server/repo/trunk
paths:
  - path: src/core
    depth: infinity
  - path: src/utils
    depth: files
  - path: docs
    depth: empty
```

Apply it to a working directory:

```bash
sparsesvn apply --url svn://server/repo/trunk -C ./myrepo
```

On subsequent runs, if the config hasn't changed, sparsesvn detects no diff and exits immediately (fast path).

## Configuration File Schema

Default location: `./sparsesvn.yaml` (override with `-f`).

```yaml
url: svn://server/repo/trunk    # optional: SVN repository root URL; CLI --url overrides this
paths:
  - path: src/core              # required: relative path from url
    depth: infinity             # required: empty | files | infinity
  - path: src/utils
    depth: files
  - path: docs
    depth: empty
```

### Field rules

- **`url`**: Optional. If omitted, you must pass `--url` on the CLI. If both are set, `--url` takes precedence.
- **`paths[].path`**: Required, non-empty string. Use forward slashes `/` (even on Windows). No leading `/`, no trailing `/`, no `..` segments. Each path must be unique.
- **`paths[].depth`**: Required. One of:
  - `empty` — directory exists but no files or children
  - `files` — directory contents only, no recursive children
  - `infinity` — full recursive checkout
- **Parent directory auto-expansion**: If you list `src/core/utils` with `infinity`, sparsesvn automatically ensures `src` and `src/core` are checked out at `empty` depth (unless you explicitly declare them with a deeper depth).

## Subcommand Reference

### `sparsesvn apply`

Apply configuration to working copy (checkout + set-depth operations).

```
sparsesvn apply [--url URL] [-r REV] [--dry-run]
```

| Flag | Description |
|------|-------------|
| `--url URL` | Override URL from config |
| `-r, --revision REV` | Pin to specific SVN revision |
| `--dry-run` | Show plan without executing |

| Exit code | Meaning |
|-----------|---------|
| 0 | Success or fast-path (already in sync) |
| 1 | General failure |
| 2 | Config error, URL mismatch, or URL required |
| 3 | SVN command execution failure (half-state written) |

### `sparsesvn plan`

Show planned actions without executing anything.

```
sparsesvn plan [--url URL] [-r REV]
```

Supports `--json` for machine-readable output.

### `sparsesvn status`

Check if working copy is in sync with config.

```
sparsesvn status [--url URL]
```

| Exit code | Meaning |
|-----------|---------|
| 0 | In sync |
| 1 | Has diff (actions listed) |
| 2 | Config/URL error |

Supports `--json`.

### `sparsesvn validate`

Validate configuration file syntax and schema rules. Does not connect to SVN or read state.

```
sparsesvn validate
```

### Global flags

| Flag | Description |
|------|-------------|
| `-f, --file PATH` | Config file path (default `./sparsesvn.yaml`) |
| `-C, --workdir PATH` | Working copy directory (default `.`) |
| `-v, --verbose` | Increase verbosity (can be stacked: `-v`, `-vv`) |
| `-q, --quiet` | Suppress non-error output |
| `--json` | Machine-readable JSON output (plan/status) |
| `--no-color` | Disable colored output |

## State File

Location: `<workdir>/.svn/sparsesvn.state.yaml`

This file records the last successfully applied state: which paths are checked out, at what depth, the config hash, and the repository URL. sparsesvn uses it for:

1. **Fast-path detection**: If config hash matches, skip all SVN operations.
2. **Diff computation**: Compare desired (config) vs current (state) to determine actions.
3. **URL consistency**: Prevent accidentally applying a config meant for a different repository.

**Do not edit this file manually.** It is managed by sparsesvn.

**When to delete it**: If the file becomes corrupted or you want a full rebuild, delete it and run `apply` again. sparsesvn will perform a fresh checkout and recreate the state file.

## Typical Workflows

### New clone

```bash
# First time: creates working copy and writes state file
sparsesvn apply --url svn://example.com/repo/trunk -C ./myrepo
```

### Modify config and apply

```bash
# Edit sparsesvn.yaml to add/remove/change paths

# Preview what would change
sparsesvn plan -C ./myrepo

# Apply changes
sparsesvn apply -C ./myrepo
```

### CI pipeline

```bash
# Use --json for machine-readable output
sparsesvn plan -C ./myrepo --json | jq .

# Or just apply directly
sparsesvn apply --url svn://example.com/repo/trunk -C ./myrepo
```

## Migrating from the Ruby `checkout.rb`

The original Ruby script used a different configuration format. Here's how to migrate:

### Schema changes

| Ruby `checkout.rb` | sparsesvn |
|--------------------|-----------|
| `@` suffix on path (e.g., `src@`) | Explicit `depth: files` |
| `*` suffix on path (e.g., `src/*`) | Explicit `depth: infinity` |
| No suffix | Explicit `depth: empty` |
| `include` directive for nesting | Not supported — merge paths manually |
| Platform filter (`linux`, `windows`) | Not supported — use separate YAML files |

### Example migration

**Old Ruby format:**
```
src@
docs
tests/*
```

**New sparsesvn YAML:**
```yaml
url: svn://server/repo/trunk
paths:
  - path: src
    depth: files
  - path: docs
    depth: empty
  - path: tests
    depth: infinity
```

### Platform filtering

The Ruby script supported platform-specific paths. sparsesvn does not. If you need platform-specific configurations, maintain separate YAML files and select the appropriate one in your CI pipeline:

```bash
# Linux CI
sparsesvn apply -f sparsesvn-linux.yaml -C ./myrepo

# Windows CI
sparsesvn apply -f sparsesvn-windows.yaml -C ./myrepo
```

## Troubleshooting

### "url required: provide in config or --url flag"

Your config file doesn't have a `url` field and you didn't pass `--url`. Either add `url:` to your YAML or pass `--url` on the command line.

### "url mismatch with state file"

The URL in your state file doesn't match the URL in your config or `--url` flag. This usually happens when you switch repositories. Delete `.svn/sparsesvn.state.yaml` and run `apply` again.

### "state file corrupt; delete it to trigger full rebuild"

The state file YAML is malformed. Delete `.svn/sparsesvn.state.yaml` and run `apply` again.

### "state file version newer than supported; please upgrade sparsesvn"

Your state file was created by a newer version of sparsesvn. Upgrade your sparsesvn binary.

### SVN command fails with exit code 3

An SVN operation failed (e.g., permission denied, path doesn't exist on server). sparsesvn writes a "half-state" file so the next run can resume from the actual working copy state. Fix the underlying SVN issue and run `apply` again.
