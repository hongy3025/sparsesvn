## 四、本会话学到的新经验（追加到旧文档第七节）

### 子智能体 / write 工具的提示词长度限制

- **task tool 的 prompt** 实测约 **8KB 上限**，超出被截断（错误：`JSON Parse error: Unterminated string`）
- **write tool 的单次 content** 也有类似 ~8KB 上限
- 解决：精简提示词去重；写大文件分两段（先 write，再 edit 追加）

### 控制者直接执行的判断标准（已验证）

- **M1-7 Action 类型**：4 个枚举 + 1 个 String() switch，纯机械，控制者直接做
- **M1-8 Expand**：算法 12 行 + 7 个测试，逻辑简单可视化，控制者直接做
- 验证规则：算法 < 20 行、测试 < 200 行、无架构决策 → 控制者直接做
- 反之（如 M1-9 Diff），即便代码不长，**核心算法**仍坚持独立分派 + 两阶段审查

### 审查者反馈中的「跨任务决策」

- M1-6 代码审查出现「M3 错误消息分层」建议，被标注为「M2 阶段统一处理」——**跨任务决策不要在当前任务修复**，记录到下一里程碑提醒即可
- M1-9 审查中的「slice 容量预分配」是 MINOR，可在后续顺手优化

### 与旧文档的一处偏差（已确认）

- 旧文档第十节提到 `DepthExclude` 常量，实际 `internal/config/config.go` 只有 3 个常量（empty/files/infinity）。规格中 `exclude` 是 svn CLI 选项语义而非 depth 值，**当前实现正确**，旧文档表述瑕疵忽略即可
